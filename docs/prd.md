# Dooray MCP Server 고도화 요구사항

작성 기준일은 2026-08-06이다.

이 문서는 `dooray-cli` v0.16.0 기능을 독립적인 Kotlin MCP 서버로 옮기기 위한 제품 요구사항을 정의한다.
CLI 저장소는 검증된 동작을 확인하는 참고 자료로만 사용한다.
서버는 CLI 실행 파일, 패키지, 소스 모듈, Docker 이미지에 의존하지 않는다.

## 목표

Dooray MCP Server는 Dooray 프로젝트, 업무, 댓글, 첨부, 위키, 메일, 메신저 기능을 MCP 클라이언트에서 안전하게 호출할 수 있게 한다.

완료 시 다음 조건을 만족해야 한다.

- `dooray-cli` v0.16.0의 66개 말단 명령과 공통 실행 계약 15개가 기능 대응표에 모두 존재한다.
- 기능 대응표의 모든 행은 `implemented` 또는 `mcp-native-equivalent` 상태다.
- 기존 `legacy` 도구의 이름, 입력, 텍스트 결과 호환성을 유지한다.
- 새 기본 도구 집합은 12개 도메인 도구로 구성한다.
- `compact`, `legacy`, `all` 도구 프로필을 시작 시 한 번 선택한다.
- 삭제와 자격 증명 제거 같은 손실 작업은 준비와 확정 두 단계로만 실행한다.
- 비밀 값은 도구 입력, 결과, 로그, 상태 파일에 원문으로 남기지 않는다.
- Docker 이미지는 CLI 없이 독립 실행된다.

## 범위

### 포함

- 서버 설정, 진단, 캐시, 버전과 환경 진단
- 구성원 조회, 목록, 검색, 이름과 이메일 해석
- 프로젝트 목록, 구성원, 업무 흐름, 구성원 그룹, 태그, 업무 템플릿
- 업무 목록, 검색, 상세, 생성, 수정, 완료, 흐름 변경, 상위 업무 지정
- 담당자, 참조자, 그룹 담당자, 그룹 참조자, 태그, 멘션, 업무 링크
- 업무 댓글 조회, 최신 댓글, 상세, 생성, 수정, 삭제
- 업무와 댓글 첨부의 목록, 업로드, 다운로드, 일괄 다운로드, 삭제
- 위키 목록, 페이지 목록, 페이지 트리, 상세, 생성, 수정, 삭제
- 위키 첨부와 위키 댓글 기능 전체
- IMAPS 메일 목록과 상세, SMTPS 메일 전송과 답장, 저장된 메일 인증 정보 제거
- 개인 또는 채널 대상 메신저 전송과 구조화된 전송 결과
- 구조화 결과, 안정 오류 코드, 재시도 가능 여부, 변경 요청 중복 방지
- 다중 아키텍처 Docker 이미지와 MCP 클라이언트 연결 검증

### 제외

- MCP 서버에서 `dooray` CLI 프로세스 실행
- `@bifos/dooray-cli` 패키지 의존성 추가
- CLI 내부 모듈 가져오기
- MCP Docker 이미지에 CLI 설치
- 원격 HTTP MCP 전송
- macOS Keychain 기반 메일 자격 증명 저장소의 1차 구현
- Dooray 웹 화면에서 직접 연결했지만 API에 나타나지 않는 첨부의 추정 보완

## 사용자 결과

CLI의 터미널 상호작용은 MCP 방식으로 바꾼다.
같은 사용자 결과를 제공하되 실행 방식은 MCP 계약에 맞춘다.

| CLI 개념 | MCP 결과 |
| --- | --- |
| `--json` | `structuredContent`와 `outputSchema` |
| `--quiet` | `result_mode=ids` 또는 간결한 식별자 필드 |
| `stderr` | MCP 오류와 `meta.warnings`의 분리 |
| 종료 코드 | 안정 오류 코드와 `retryable` |
| `$EDITOR` | 명시적인 본문 입력 필드 |
| `--dry-run` | `dry_run=true`의 변경 계획과 확인 토큰 |
| TTY 삭제 확인 | 5분 유효한 준비·확정 토큰 |
| 설정 마법사 | 서버 설정, `doctor`, 리소스 문서 |
| CLI 스킬 설치 | MCP 클라이언트 설정 문서와 리소스 안내 |

## 도구 프로필

최종 목표 기본값은 `compact`다.
마이그레이션 기간에는 하위 호환성을 위해 릴리스별 기본값을 명시한다.

| 프로필 | 도구 수 | 용도 |
| --- | ---: | --- |
| `compact` | 12 | 66개 CLI 기능을 도메인별 `operation`으로 제공한다. |
| `legacy` | 20 | 기존 19개 도구와 PR #28의 위키 댓글 목록 도구를 보존한다. |
| `all` | 32 | 전환 검증과 점진 이행을 위해 두 집합을 함께 등록한다. |

도구 프로필은 `DOORAY_MCP_TOOL_PROFILE`로 시작 시 선택한다.
실행 중 도구 집합은 바꾸지 않으며 `tools.listChanged=false`를 선언한다.

`compact` 프로필의 도구 목록은 다음과 같다.

| 도구 | 담당 범위 |
| --- | --- |
| `dooray_server` | 서버 설정 상태, 진단, 캐시, 설치 안내 리소스, 피드백 미리보기 |
| `dooray_project` | 프로젝트와 프로젝트 메타데이터 조회 |
| `dooray_member` | 구성원 조회, 목록, 검색 |
| `dooray_post` | 업무 조회, 생성, 수정, 상태 변경 |
| `dooray_post_comment` | 업무 댓글 생명주기 |
| `dooray_project_attachment` | 업무와 업무 댓글 첨부 |
| `dooray_wiki` | 위키 목록, 페이지 목록, 페이지 트리 |
| `dooray_wiki_page` | 위키 페이지 본문 생명주기 |
| `dooray_wiki_attachment` | 위키 첨부 |
| `dooray_wiki_comment` | 위키 댓글 |
| `dooray_mail` | 메일 조회, 전송, 답장, 인증 정보 제거 준비 |
| `dooray_messenger` | 개인과 채널 메시지 전송 |

CLI의 `setup`과 `skill install`은 `dooray_server`가 같은 동작을 로컬에 복제하지 않는다.
`doctor`, `config_status`, `resources/install-guide`로 같은 사용자 결과를 제공한다.

## 비기능 요구사항

- 표준 입출력 전송만 제공하고 로그는 `stderr`로만 쓴다.
- 조회 작업만 제한적으로 자동 재시도한다.
- 생성, 수정, 삭제, 업로드, 발송은 결과가 불명확할 때 자동 재시도하지 않는다.
- 변경 도구는 `request_id`를 받아 같은 서버 인스턴스 안의 중복 호출을 합친다.
- 파일은 MCP 리소스를 기본 전달 방식으로 사용한다.
- `content_base64`는 작은 파일에만 허용한다.
- 서버 로컬 경로는 허용된 루트 안에서만 사용한다.
- Docker 실행은 입력, 출력, 상태, 비밀 볼륨을 분리한다.
- 실제 Dooray 삭제 API나 외부 사용자에게 영향을 주는 시험은 자동으로 실행하지 않는다.

## 성공 지표

- 기능 대응표 행 수: CLI 말단 명령 66개와 공통 실행 계약 15개
- 도구 프로필 수: 3개
- 최종 도구 수: `compact=12`, `legacy=20`, `all=32`
- 기존 20개 `legacy` 도구 하위 호환 시험 통과
- 새 compact 도구 스키마와 결과 스냅숏 시험 통과
- 구조화 오류 코드와 `isError=true` 시험 통과
- 삭제 준비, 확정, 만료, 대상 불일치 시험 통과
- Docker `linux/amd64`, `linux/arm64` 이미지 빌드 검증
