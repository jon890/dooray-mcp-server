# ADR 0004: 파일 전송 경계

상태: 승인됨

## 결정

파일 전송의 기본 방식은 MCP 리소스다.
작은 파일은 `content_base64`를 허용하고, 서버 로컬 경로는 허용 목록에 들어간 루트 안에서만 허용한다.

Docker 실행은 다음 마운트 경계를 사용한다.

| 경로 | 권한 | 용도 |
| --- | --- | --- |
| `/data/in` | 읽기 전용 | 업로드 입력 |
| `/data/out` | 쓰기 가능 | 다운로드 출력 |
| `/data/state` | 쓰기 가능 | 상태와 임시 리소스 |
| `/run/secrets` | 읽기 전용 | 비밀 파일 |

## 근거

MCP 클라이언트와 MCP 서버가 같은 파일시스템을 공유한다고 가정할 수 없다.
로컬 경로를 기본 입력으로 삼으면 Docker, 원격 호스트, 샌드박스 환경에서 실패하거나 잘못된 파일을 읽을 수 있다.

파일 본문을 항상 base64로 반환하면 큰 첨부에서 메모리와 토큰 비용이 커진다.
따라서 리소스 임대가 기본 경계가 된다.

## 결과

업로드는 리소스 URI 또는 base64가 기본이다.
다운로드는 `delivery=resource`가 기본이다.
서버 경로 입출력은 명시 설정 없이는 실패한다.
경로 오류는 `LOCAL_PATH_FORBIDDEN`, `OUTPUT_EXISTS`, `RESOURCE_UNREADABLE` 같은 구조화 오류로 반환한다.
