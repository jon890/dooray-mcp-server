# Dooray MCP 팀 구현 오버레이

공용 `build-with-teams` 스킬을 사용할 때 이 저장소의 작업 분리와 검증 계약을 적용한다.

## 작업자 소유권

- 작업자는 배정된 계획과 파일만 수정한다.
- `DoorayMcpServer.kt`, 공통 도구 등록, 공통 오류 모델, 기능 대응표는 동시에 두 작업자가 수정하지 않는다.
- 공통 계약 변경이 필요하면 선행 계획으로 올리고 후속 작업자는 그 계약을 소비한다.
- 다른 작업자의 변경을 되돌리거나 재작성하지 않는다.

## 실행 순서

1. 기반 구조와 오류 계약
2. 설정·진단·상태·캐시
3. 프로젝트·멤버·resolver
4. 업무
5. 업무 댓글
6. 파일 리소스와 업무 첨부
7. 위키·페이지·댓글
8. 위키 첨부
9. 메일
10. 메신저
11. 삭제 안전 정책
12. 로컬 관리 기능
13. 문서·Docker·릴리스

선행 공통 계약이 병합된 뒤에는 파일 소유권이 겹치지 않는 도메인을 병렬로 진행할 수 있다.

## 작업자 완료 조건

- 맡은 기능의 입력 스키마와 구조화 결과가 테스트된다.
- Dooray 요청·응답 계약이 가짜 서버나 모의 전송으로 검증된다.
- 실제 자격 증명이나 개인 식별 정보가 추가되지 않는다.
- `CI=true ./gradlew clean build --no-daemon --console=plain`을 통과한다.
- 해당되는 경우 `./gradlew testMcpIntegration --no-daemon --console=plain`을 통과한다.
- `git diff --check`를 통과한다.
- 독립 검토자와 문서 검증자의 지적을 반영한다.

## 리더 완료 조건

- 작업자의 검증 출력을 직접 확인한다.
- PR 리뷰, 인라인 댓글과 미해결 스레드를 확인한다.
- 외부 게시문은 `content-preview` 절차를 거친다.
- CI 통과 뒤 저장소의 기존 병합 방식을 사용한다.
- 병합된 작업 트리만 정리한다.
